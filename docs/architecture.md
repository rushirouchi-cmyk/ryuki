## コンポーネント

### 1. Orchestrator Agent

- ユーザーからの自由入力を受け取り、業務カテゴリ (JD 作成 / スカウト / パイプライン管理 …) に振り分ける。
- 単一タスクなら該当サブエージェントを 1 回呼ぶ。複数タスクにまたがるなら順序付けして委譲する。
- 実装: Claude Code のトップレベル会話 + `.claude/agents/*.md` によるサブエージェント定義、または Claude Agent SDK の `subagents` 設定。

### 2. サブエージェント群

`docs/agent-responsibilities.md` に責務分担を詳述。ここでは名前と役割の一言サマリーのみ。

| エージェント | 役割 |
| --- | --- |
| JD Author | 求人票の起草・改訂 |
| Scout Writer | 媒体別スカウト文の生成 |
| Sourcing (v2) | 候補者検索とロングリスト作成 |
| Scheduler (v2) | 面接候補日調整と招待送付 |
| Pipeline Analyst | 選考ステータス集計と週次レポート |

### 3. MCP Tool Layer

- **自作 MCP (`mcp-server/`)**: 採用業務固有のドメインロジックを閉じ込める。ATS が Greenhouse でも Lever でも、上位からは同じ interface で叩けるように抽象化する。
- **既存 MCP**: 汎用サービスは既存の MCP サーバーを流用し、車輪の再発明はしない。

### 4. データストア

- **求人・候補者・選考ステータス**: ATS を単一の情報源 (Source of Truth) とする。ryuki-mcp はキャッシュだけを持つ。
- **テンプレート・KPI 集計結果**: Google Drive + 軽量な KV (SQLite など) をローカルに置く。運用が回ってから DB 化を検討。
- **面接記録**: tldv を参照する (自前で音声を持たない)。

## 認証・シークレット

| 対象 | 方式 |
| --- | --- |
| ATS API | 各社発行のトークンを環境変数経由で MCP サーバーに渡す |
| スカウト媒体 | API がある媒体はトークン、無い媒体は将来的に Playwright + Cookie |
| Google 系 | 既存 MCP の OAuth 認証を利用 |
| ATS Webhook (将来) | 署名検証必須 |

シークレットは `.env` を Git にコミットせず、デプロイ環境の Secret Manager に格納する。

## 非機能要件

- **監査ログ**: エージェントが送ったメール・スカウト・ATS 更新は全て台帳に記録する (誰が / いつ / 何を)。
- **ヒューマン・イン・ザ・ループ**: 候補者に対する外向きアクション (メール送信・スカウト送信・ステータス確定) は原則ドラフト作成までとし、送信は人間の承認を挟む。
- **PII 取り扱い**: 候補者の氏名・連絡先・現年収などは MCP ログにも残さない。ID で参照する。
