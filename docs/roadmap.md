---

## Phase 1: MVP (求人票作成 + パイプライン参照)

### スコープ
- JD Author Agent 稼働
- Pipeline Analyst Agent 稼働 (読み取り専用)
- ryuki-mcp: JD テンプレート系 + pipeline 集計系
- ATS 連携は 1 社のみ (最初に契約している ATS)

### 除外
- 外向き I/O (スカウト送信・メール送信)
- 面接調整
- 候補者ソーシング

### 完了判定
- 「Sales Manager の JD ドラフト作って」で 30 秒以内にドラフトが返ること
- 「今週のパイプライン」で TL;DR + テーブルが返ること
- 監査ログが全書き込みで記録されていること

**推定期間**: 3〜4 週間

---

## Phase 2: スカウト送信 (承認フロー付き)

### スコープ
- Scout Writer Agent 稼働
- ryuki-mcp: `scout_send` を 1 媒体で実装 (Wantedly か BizReach)
- 送信は必ずユーザー承認を挟む UI (Slack ボタン / Web)

### 完了判定
- 「候補者 C-XXX にスカウト作って」で A/B 2 案が返る
- 選択・承認後に 1 発で送信され、監査ログに記録される
- `idempotency_key` の重複送信テストが通る

**推定期間**: 3〜4 週間

---

## Phase 3: 候補者ソーシング

### スコープ
- Sourcing Agent 稼働
- ryuki-mcp: `candidate_search` を各媒体で実装
- ロングリスト → 一次スクリーニング → Scout Writer への引き渡し

### リスク
- スカウト媒体の API が制限的な場合、Playwright での自動化を検討 (要 ToS 確認)。

**推定期間**: 4〜6 週間

---

## Phase 4: 面接調整

### スコープ
- Scheduler Agent 稼働
- Google Calendar / Gmail 経由の候補日提示・確定
- tldv 連携で面接後の書き起こしを ATS メモに紐付け

**推定期間**: 3〜4 週間

---

## Phase 5: 拡張

- ATS 2 社目・3 社目対応
- Slack ボットとして常駐
- 面接評価の集計 (面接官バイアス検知)
- 内定辞退リスク予測

---

## 非目標 (当面やらない)

- **自動意思決定**: 合否判定を AI に任せない。常に「人が最終判定できる材料」を作る。
- **候補者向けチャットボット**: 送信内容の統制が難しい。フェーズ 5 以降で慎重に検討。
- **多言語すべて対応**: 当面 JP / EN のみ。他言語は要件ベースで追加。
